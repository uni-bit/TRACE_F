# 実装依頼書: フットプリントを図面の枠線から起こす / EVシャフトの縦線を消す

宛先: Codex / 発行: Claude(レビュー) / ブランチ: `feat/floor-map-rebuild`(HEAD `1e145b7`)

## A. 連絡通路などの床が図面の枠線とまったく合っていない

### 事実

前回追加した6つの構造対象のフットプリントは、**全部が矩形1個**で、しかも
ほぼクロップ全域を覆っている:

| 対象 | 頂点数 | bbox |
| --- | --- | --- |
| west-connector | 4 | `0,0 - 460,190`(クロップ全域) |
| east-connector | 4 | `0,0 - 130,140`(クロップ全域) |
| deck | 4 | `0,0 - 590,1600`(クロップ全域) |
| roof-garden | 4 | `25,23 - 475,784` |
| shared-west | 4 | `22,24 - 472,376` |
| shared-east | 4 | `21,22 - 373,659` |

つまりスラブが**図面の輪郭ではなく切り出し矩形の形**で出ている。渡り廊下の
周りに出ている「謎の床」はこれ。カバレッジのフロア単位指標が 0.0% なのも当然で、
全部を覆う矩形は何一つ取りこぼさない —— **指標が意味を持っていない**。

### やること —— 枠線の中を塗る

フットプリントを手で矩形に書くのをやめ、**図面のシアン線が囲む領域から起こす**。
必要な処理は既に書いたことがあるもの(旧 `pipeline/context.py` の輪郭トレース)と同じ:

1. クロップのシアンマスク
2. 方向を問わない `MORPH_CLOSE` で線の途切れを塞ぐ
3. `cv2.findContours(RETR_EXTERNAL)` で外輪郭
4. 面積閾値でゴミを落とし、`cv2.approxPolyDP` で頂点を間引く(目標 40 頂点以下)
5. マスター矩形 px の多角形として `footprints` に書く

- **6つの構造対象すべてに適用する。** 対象が複数の塊に分かれる階(1F共用部など)は、
  フットプリントを複数持てるようにするか、塊ごとに対象を分けるか、実装しやすい方でよい
- 4棟(教室棟・研究棟・交流棟・本部棟)は前回フロア別に実測したばかりで
  カバレッジが 4% 未満に収まっているので、**この依頼では触らない**。
  ただし同じトレースを掛けた場合の結果を比較して報告すること
  (手実測より良いなら次で置き換える)

### カバレッジ指標の穴も塞ぐこと

フットプリントがクロップ全域だと「外側 0%」になって素通りする。
**フットプリント面積がクロップ面積の一定割合(例 85%)を超えたら警告**を出すこと。
「全部塗れば満点」という抜け道を残さない。

### 合格条件

- 6対象すべてのフットプリントが図面の枠線に沿っている(4頂点の矩形ではない)
- 渡り廊下の周囲に、図面に線の無い床が出ていない
- 新しい警告が、6対象について解消されている

## B. EVシャフトの縦白線が主張しすぎ

### 事実

`floor-map-viewer.ts` の `SHAFT_OPACITY = { solid: 0.12, edges: 0.3 }`。
シャフトは「半透明の箱」と「四隅の縦エッジ線(`0xd8fff0`、opacity 0.3)」の
2つで描かれていて、階を1つ選ぶと**床がほぼ消えるのに縦線だけが全階分残る**ため、
画面でいちばん目立つ要素になっている。

### やること

- **四隅の縦エッジ線(`LineSegments`)を削除する。** 薄い箱だけ残す
- `buildElevatorShaft` が `edges` を返す必要がなくなるなら、そちらも整理すること
  (使われないジオメトリを生成したままにしない)
- 箱の不透明度は現状の 0.12 のまま。上げないこと

### 合格条件

- 階を1つ選んだとき、縦に走る白い線が無い
- EV の位置は薄い箱で分かる
- ALL 表示でも同様
