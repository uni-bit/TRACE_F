## A. 吹き抜けから下階のエスカレーターが透けて「ごちゃごちゃ」に見える

### 症状

4F を選択したとき、廊下の吹き抜けの中に細い平行線の束が見える。
ユーザーはこれを「消したはずの謎の細い線」と受け取っている。

### 原因(調査済み・図面インクではない)

その位置(マスター矩形 px で z≈726〜902)にあるのは **3F のエスカレーター
ジオメトリ**。4F の吹き抜けはスラブも平面図シートも貫通しているので、下階が
そのまま見えている。図面記号は 3F/4F とも既に穴で抜けている(確認済み)。

なぜ dimmed(0.03)なのに見えるのか: 直前のコミットでエスカレーターを
「デッキ + 踏段16 + 欄干2 + ハンドレール2」×2レーン + 乗降板2 = **42個の
半透明ボックス**にした。`depthWrite: false` なので視線上で α が累積し、
0.03 × 40枚 ≈ 実効 0.26 になる。薄いはずのものが束になって見えている。

### やること

`src/lib/map/floor-map-viewer.ts` の `OPACITY.dimmed`:

- `core: 0.03 → 0`
- `furniture: 0.01 → 0`(同じ理由。机は1教室あたり数十個ある)

さらに `writeFloorTones()` で、**opacity が 0 のメッシュは `visible = false` に
する**。透明でも描画はされるので、ブルームへの寄与とドローコールが残るため。
マテリアル単位ではなくメッシュ単位で切る必要があるので、`FloorHandle` に
対象メッシュの参照を持たせるか、`group.traverse` で material 同一性を見て切る。

`selected` / `all` は変更しない。ALL ビューでは下階の縦動線が見えてよい
(あれが「棟を貫く動線」の説明になっている)。

### 合格条件

- 4F 選択時、吹き抜けの中が**空**(地面のグリッドだけが見える)
- ALL では今まで通りエスカレーターが見える
- 階を切り替えたときのトゥイーンが破綻しない(visible の切り替えは
  opacity が 0 に**到達してから**、0 から離れるときは**先に** true にする)

## B. 吹き抜けの縁と壁がずれている

### 原因

`src/lib/map/toyosu-classroom.features.json` の `voids` の実測ミス。
`scripts/floorplan/debug/crop-*.png` にグリッドを重ねて読み直した実測値が下表。
とくに **4F が致命的**で、下辺が壁線より 80px 下(車イス記号のある廊下まで)
飲み込んでいる。右辺は全階共通で 4〜6px 外側にずれている(壁線の外側を
拾っている。芯を取ること)。

| 階 | 種別 | 現在値 | 実測値 | 差分 |
| --- | --- | --- | --- | --- |
| 4 | atrium | `[320,690,478,1228]` | **`[318,722,474,1148]`** | 上-32 / 右+4 / **下+80** |
| 3 | atrium | `[318,905,478,1222]` | `[318,902,474,1218]` | 右+4 / 下+4 |
| 5 | atrium | `[318,730,478,1068]` | `[318,725,472,1063]` | 右+6 |
| 6 | atrium | `[318,730,478,988]` | `[318,725,472,985]` | 右+6 |
| 2 | escalator-well | `[316,1145,388,1360]` | `[318,1148,375,1350]` | 右+13 / 下+10 |
| 5 | escalator-well | `[320,450,388,610]` | `[318,448,390,612]` | ほぼ正 |
| 6 | escalator-well | `[318,450,385,612]` | `[318,448,390,612]` | ほぼ正 |
| 2 | atrium | `[486,470,643,600]` | **`[518,468,645,598]`** | **左-32** / 右-2 |

`escalators` 側も 2F `es-mid` の右辺が 386 → 実測 375、3F `es-n` の右辺が
386 → 実測 372。ついでに直すこと(穴の大きさに効く)。

### 実測のやり方

計測用ツールは**こちらで用意済み**(`scripts/floorplan/grid_probe.py`、未コミット)。

```
python scripts/floorplan/grid_probe.py 4 300 640 500 1290 2
```

`debug/crop-{floor}.png` の指定領域を拡大し、25px ごとに座標ラベル付きの
グリッドを重ねて `debug/grid-{floor}.png` に出す。上表の実測値はこれで読んだ。
**壁線の外側ではなく芯を取ること** —— 右辺の系統誤差はそれが原因。

### 合格条件

- 各 `voids` の四辺が、図面の実線(バッテンを囲む矩形)の**芯**に対して ±4px
- 3Dで、吹き抜けの縁とその縁に立つ壁がぴったり合っている(4F を重点確認)
- `npx tsc --noEmit` / `npx eslint src` クリーン(features.json はロード時に
  検証が走るので、範囲外の値を書くと起動時に throw する)

## C. 周辺建物への拡張(新規)

### 要望

「今は教室棟だけで、ぶつ切りになっていて不自然。周辺も出してほしい。
使うかどうかは別として。」

### 素材の状況(調査済み)

同じPDFの同じページに、**キャンパスの配置どおりに**他の棟が描かれている。
600dpi ページ座標での実測:

- 教室棟(現行 `masterRect`): `x 632, y 1196, w 912, h 1514`
- 研究棟: 教室棟の右上、`x ≈ 2090〜2800, y ≈ 1200〜1900`
- カフェテリア: 左下、`x ≈ 870〜1320, y ≈ 2880〜3920`
- 本部棟(2301〜2306教室・阿出川シアター・PRAYER ROOM): 中央下、
  `x ≈ 1560〜2680, y ≈ 3000〜4290`
- シアン画素の全体範囲(右のタブ列を除く): `x 307〜2831, y 555〜4369`
  ただし `y < 900` はページ上端の斜線バナー、左下は凡例アイコンなので除外対象

### 設計方針(重要)

**既存のマスター矩形は動かさないこと。** `features.json` のアノテーションは
すべてマスター矩形 px で書かれているので、矩形を広げると全部が壊れる。

代わりに `config.json` に **`contextRect`** を足す:

```jsonc
"contextRect": { "x": 600, "y": 1150, "w": 2260, "h": 3220 }
```

- `masterRect` は `contextRect` の内側にある。両者は同じページ座標系・同じ
  レジストレーション結果を共有するので、**追加の位置合わせは不要**
- world 変換は既存のスケールを流用する。`PLAN_WORLD_WIDTH / masterRect.w`
  が px→world の倍率なので、コンテキスト側の点は
  `worldX = (ctxPx.x + contextRect.x - masterRect.x) * scale - PLAN_WORLD_WIDTH/2`
  で置ける。`plan-transform.ts` に `contextPxToWorld()` を1本足す形が素直
- パイプラインは `crop.py` にコンテキスト用の切り出しを追加し、
  `public/floorplans/context/floor-{floor}.png` を出す。壁抽出は**やらない**
  (周辺棟は塊で十分)

### 3D 表現

周辺棟は**マッシング(塊)**として出す。教室棟と同じ密度で作らないこと
—— 主役が埋もれるうえ、図面の精度も担保できない。

- 手描きアノテーション `neighbors[]`(コンテキスト矩形 px の多角形 + 階数 +
  名前)を `toyosu-context.features.json` として新規に持つ
- 各棟 = フットプリント多角形を `階数 × LEVEL_HEIGHT` だけ押し出した1個の
  `ExtrudeGeometry`。壁も什器も要らない
- マテリアルは教室棟より**確実に沈む**トーン(彩度を落としたミント、
  opacity 0.12〜0.18、`depthWrite: false`)。輪郭線だけ少し強く出す
- 階選択・ALL 切り替えの対象外(常時同じ見た目)。EV シャフトと同じく
  フロアグループの**外側**に置く(選択リフトで動いてはいけない)
- 地面(`GROUND_Y`)より上、y=0 から立ち上げる

### 段階

1. `contextRect` 追加 + コンテキストクロップ出力 + デバッグ画像で位置確認
2. `neighbors` アノテーション(4棟ぶん。多角形は粗くてよい)
3. マッシング描画 + トーン調整
4. カメラの `maxDistance` / フォグ / 地面サイズの見直し(範囲が2倍以上に
   広がるので、今の値だと見切れる・霧で溶ける)

### 合格条件

- 教室棟の見た目が**1ピクセルも変わらない**(既存アノテーションを触っていない証拠)
- ORBIT を引いたとき、教室棟が周辺棟の中に建っていて、ぶつ切り感がない
- 周辺棟が主役を食っていない(パッと見て教室棟がどれか即座に分かる)
- ビルド・型・Lint クリーン、フレームレートが落ちていない
