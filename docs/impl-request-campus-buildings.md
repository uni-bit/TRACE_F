# 実装依頼書: 周辺棟を教室棟と同じ粒度で作る

宛先: Codex / 発行: Claude(調査・レビュー) / ブランチ: `feat/floor-map-rebuild`(HEAD `046e542`)

ユーザー決定: **周辺棟も教室棟と完全に同じ粒度**(階ごとのスラブ・壁・平面図
テクスチャ + 吹き抜け・縦動線・什器の手アノテーション)。
現在の「概略マッシング(押し出した箱)」は、実棟に置き換わり次第削除する。

## 素材の確認(実測済み)

PDF の `index 58〜71` が **1F〜14F**。1ページ = 1フロアで、その階に存在する棟が
すべて描かれている。config の `pages` は 1-origin なので `index + 1`。

| 棟 | 階数(p.56 の階数表) | 該当ページ index | 備考 |
| --- | --- | --- | --- |
| ③教室棟 | 6 | 58〜63 | **実装済み(主役)** |
| ④研究棟 | 13 | 58〜70 | |
| ①本部棟 | 14 | 58〜71 | |
| ②交流棟(カフェテリア) | 6 | 58〜63 | |

**7F 以降は誌面構成が変わり、研究棟と本部棟の2棟だけになる**(index 64/70/71 で確認)。
低層階と高層階で棟の位置も大きさも違うので、**棟ごとに独立したマスター矩形と
レジストレーションが必須**。1枚の広い矩形で全棟を追う現行 `contextRect` 方式は
ここで破綻していた。

参照階(3F = index 60 = config page 61)での実測 bbox(600dpi ページ座標):

| 棟 | bbox | 備考 |
| --- | --- | --- |
| 教室棟 | `x632 y1196 w912 h1514` | 既存 `masterRect` |
| 研究棟 | `(2101,1228)-(2776,1897)` | w675 h669 |
| 交流棟 | `(871,2902)-(1313,3884)` | w442 h982 |
| 本部棟 | `(1568,3039)-(2683,4262)` | w1115 h1223 |

マスター矩形は**その棟の全階の外形の和**でなければならないので、上記に余白
(各辺 +80px 程度)を足して開始し、**どこかの階でインクが矩形の縁に触れたら
パイプラインが警告を出す**こと。触ったら矩形を広げて再生成する。

## 0. 先に潰す(ブロッカー): 図面記号が壁として抽出されている

**これを直さずに棟を増やすと、同じゴミが3棟ぶん増える。**

`?debug=layers` で `walls` を切ると、初回から指摘され続けている
「エスカレーターのごちゃごちゃ」が消える。生成データ上も:

- 2F: 全100本中 **16本**、3F: 全90本中 **18本**、4F: 全91本中 **19本** が
  エスカレーター記号の矩形内にある
- 例(4F): `(326,696)-(326,859)` / `(354,696)-(354,859)` / `(383,696)-(383,859)`
  —— レーンの縦線そのもの

記号の長い平行線は、壁抽出(§2.4)が探している「長い直線ラン」と形状が一致する。
しかも**壁は `voids` でクリップされない**ので、開口をどれだけ正しく広げても残る。

### 直し方

`walls.py` の抽出前に、**その棟の features から `stairs ∪ escalators` の矩形を
シアンマスクから消す**。記号は壁ではないので、生成データの段階で落とす
(レンダ時フィルタにしないこと。生成JSONにゴミが残る)。

- 矩形はマスター矩形 px。壁抽出はマスター矩形基準なので変換は不要
- アノテーションがまだ無い新規棟では、初回生成時は記号が壁として出る。
  アノテーションを入れて再生成すれば消える —— この順序を README に明記する
- **回帰ゲート**: 教室棟を再生成し、壁本数が 2F 100→84 / 3F 90→72 / 4F 91→72
  付近まで落ち、それ以外の壁が1本も消えていないこと

## 1. パイプラインの多棟化

`config.json` を棟の配列にする。共通パラメータ(dpi・cyan・walls・texture)は
トップレベルに残し、棟ごとに上書き可能とする。

```jsonc
{
  "dpi": 600, "cyan": {...}, "walls": {...}, "texture": {...},
  "referencePage": 61,
  "buildings": [
    {
      "id": "toyosu-classroom", "name": "教室棟",
      "pages": { "1": 59, ..., "6": 64 },
      "referenceFloor": "3",
      "masterRect": { "x": 632, "y": 1196, "w": 912, "h": 1514 },
      "templates": [...], "refineWindow": {...},
      "eraserRects": {...},
      "featuresJson": "src/lib/map/toyosu-classroom.features.json",
      "output": { "textureDir": "public/floorplans/classroom", "geometryJson": "..." }
    },
    { "id": "toyosu-research", "name": "研究棟", "pages": { "1": 59, ..., "13": 71 }, ... }
  ]
}
```

- `build.py` は棟ごとにループ。**教室棟の生成物が §0 の記号除去以外で
  1バイトも変わらないこと**が、このリファクタの合格条件
- テンプレートは棟ごとに選び直す。教室棟と同じ「階段コアの複数テンプレート +
  2枚以上が ±48px で合意するクラスタ」方式(§2.2)を流用する
- **どの階でもクラスタが作れなかったら、その棟・その階で fail する**こと。
  黙って 0 シフトにしないこと(v1 の `planOffsetX` と同じ罠になる)
- デバッグ出力も棟ごとに分ける: `debug/<id>/crop-{floor}.png` など

## 2. 棟間の配置

**参照階1枚で確定する。** 全棟のマスター矩形が同じ参照ページ座標で定義されて
いるので、棟 B の原点は

```
worldOffset = (B.masterRect.x - primary.masterRect.x,
               B.masterRect.y - primary.masterRect.y) * scale
scale = PLAN_WORLD_WIDTH / primary.masterRect.w
```

で決まる。追加の位置合わせも手入力のオフセットも要らない
(`plan-transform.ts` の `contextPxToWorld` と同じ考え方。あれは残して汎用化する)。

**正直さ**: これは案内図の誌面レイアウト上の並びであって測量ではない。
p.56 の俯瞰図(①本部棟 ②交流棟 ③教室棟 ④研究棟)と大筋で一致することは
確認済みだが、インスペクタと `docs/floor-map-3d.md` に一行入れること。

## 3. フロント側の多棟化

- `buildings.ts` は `BuildingDefinition[]` を返す。`toyosuClassroom` 単体 export は
  互換のため残してよいが、ビューアは配列を受け取る
- `FloorMapViewer` は棟ごとに `FloorHandle[]` を持つ。トゥイーン・不透明度・
  `?debug=layers` はすべて全棟に一様に効かせる
- EVシャフトも棟ごと
- `build-context.ts` / `context-features.ts` / `toyosu-context.*` は、
  **3棟すべてが実棟になった時点で削除**。途中の段階では、実棟になった棟だけ
  マッシングの対象から外す(二重に建たないように)

### UI(提案。異論があれば実装前に相談すること)

- フロアセレクタは **ALL / 1F〜14F**(全棟の階の和)。階を選ぶと、**その階を持つ
  すべての棟のその階**を強調する(キャンパスの水平スライス)。7F 以上を選ぶと
  教室棟・交流棟は全体が dimmed になる
- インスペクタの2D図面は「主役の棟」のもの。主役は棟セレクタで切り替える
  (既定は教室棟)
- 凡例の「周辺棟(概略マッシング)」は削除

## 4. アノテーション作業量と順序

教室棟(6階)で約50件。研究棟13 + 本部棟14 + 交流棟6 = **33階ぶん**なので
単純比で 5.5 倍。以下の順で、**1棟ずつ完成させてからレビューに出す**こと。

各棟につき:

1. マスター矩形とテンプレートを決め、`debug/<id>/overlay-registration.png` で
   共有構造が白く重なることを確認
2. `eraserRects` で宙に浮いた注記を消す
3. 壁抽出の目視(`walls-over-texture-*.png`)
4. `footprints` を実測(階ごとに違う場合はフロア別に)
5. `voids` / `stairs` / `escalators` / `elevators` を実測。
   **計測には `scripts/floorplan/grid_probe.py` を使い、壁線の芯を取ること**
   (外側を拾うと右辺が一律ずれる。前回の実例あり)
6. `preview_features.py` で2D合格を取ってから3Dへ
7. `classrooms` / `commons` は最後。無理に埋めない(教室棟でも一部のみ)

## 5. 段階とコミット

| # | 内容 | 合格条件 |
| --- | --- | --- |
| 1 | §0 記号→壁の除去 | 教室棟の壁本数が想定どおり減り、`?debug=layers` の `walls` オフと同じ見え方になる |
| 2 | §1 パイプライン多棟化(棟は教室棟1つのまま) | 生成物が段階1と完全一致 |
| 3 | §3 フロント多棟化(棟は1つのまま) | 見た目が段階2と完全一致 |
| 4 | 研究棟(13F)を追加 | 単体で教室棟と同等の見え方 |
| 5 | 交流棟(6F)を追加 | |
| 6 | 本部棟(14F)を追加 + マッシング一式削除 + UI | |

段階1〜3は**見た目が変わらないことが合格条件**のリファクタ。ここを飛ばして
棟を足すと、教室棟の回帰と新規棟の不具合が混ざって切り分け不能になる。

## 6. 検証(各段階の着地報告に必ず入れる)

1. `python scripts/floorplan/build.py` が全棟通る
2. 棟ごとの `overlay-registration.png` / `walls-over-texture-*.png`
3. `?debug=layers` で、残骸が出た場合はどのレイヤ由来かを**必ず特定して報告**
   (前回、平面図インクと断定して実際は壁だった)
4. キャプチャ: ORBIT 全景 / 各棟の近接 / 階切替
5. `npx tsc --noEmit` / `npx eslint src` / `npm run build`
6. 既存棟のテクスチャ・生成JSONの差分が意図どおりか(`git diff --stat`)
