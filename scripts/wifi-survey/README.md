# WiFi測位の下見（9/2 豊洲・教室棟）

屋内で `navigator.geolocation` が返す位置は、GPS衛星ではなく**WiFi測位**が主力になる。
そして WiFi測位は「周囲のAPが Apple / Google のデータベースに載っていること」が
前提で、載っているかを事前に知る方法がない。それを現地で調べるための2本。

| ファイル | 役割 |
|---|---|
| `scan.ps1` | 1地点で見えているAPを記録する（Windowsノートで実行） |
| `lookup.py` | 記録したBSSIDが Apple / Google のDBに載っているか調べる |

`scan.ps1` は `netsh` の**生出力をそのままJSONへ同梱する**。現地は撮り直しが
効かないので、パーサが Windows の言語や版で外れても、後から解析し直せるように
してある。パーサの正しさに当日のデータを賭けない。

## 出発前にやること（重要）

**手元のノートで1回動かして、`登録あり` が0でないことを確認する。**
自宅でも学校でもよく、場所は問わない。ここが0のままだと、当日の測定が
「APが載っていない」のか「スクリプトが壊れている」のか区別できない。

```powershell
.\scripts\wifi-survey\scan.ps1 -Label "動作確認"
```

```bash
uv run --with gsloc python scripts/wifi-survey/lookup.py tmp/wifi-survey/scan-<日付>.jsonl
```

`Apple 登録あり N / M BSSID` の N が0より大きければ、道具は動いている。

Windows の位置情報設定がオフだと `netsh` がAPを空で返すことがある。
`設定 > プライバシーとセキュリティ > 位置情報` を確認する。

Google 側も見るなら、Google Cloud で Geolocation API を有効にしてキーを発行し、
`GOOGLE_GEOLOCATION_API_KEY` に入れておく。課金設定が要る。無くても Apple 側だけで
「載っているか」は分かる。

## 当日

教室ごと・廊下ごとに、名前を付けて実行する。名前は後から図面上に置ける粒度で。

```powershell
.\scripts\wifi-survey\scan.ps1 -Label "3F 301教室 中央"
.\scripts\wifi-survey\scan.ps1 -Label "3F 302教室 中央"
.\scripts\wifi-survey\scan.ps1 -Label "3F 廊下 301前"
.\scripts\wifi-survey\scan.ps1 -Label "4F 403教室 中央" -Note "窓側"
```

同じファイルに追記されていくので、`-Out` は指定しなくてよい。
1地点あたり既定で3回スキャンする（APの見え方は数秒で入れ替わるため）。

**隣り合う教室を必ず2つ以上**測ること。この下見の目的は「測位できるか」ではなく
「**隣の教室と区別できるか**」なので、1部屋だけ測っても答えが出ない。
同じ理由で、**別の階の同じ位置**も測ると、階が分かれるかどうかも見える。

## 解析

```bash
uv run --with gsloc python scripts/wifi-survey/lookup.py tmp/wifi-survey/scan-20260902.jsonl --out tmp/wifi-survey/result.json
```

出るもの:

- **Apple登録数** — 載っていなければ、iPhone の屋内測位はその場所で何もしてくれない
- **原点からの距離** — 載っていても、キャンパスから遠い座標が登録されていれば
  測位を狂わせる。300m超が多いなら「載っている」は当てにならない。
  この診断だけ `src/lib/map/toyosu-campus.coordinates.json`（マップ側の成果物）を
  使うので、それが無いブランチでは省略される
- **Google の推定座標と精度半径** — 実際に端末が受け取るのと同じ推定。
  `considerIp: false` を付けているので、測位できなければ 404 が返る。
  これが返ったら、その地点は Google 側では測位不能で確定
- **地点間の距離** — 各地点のGoogle推定どうしの距離。**ここが本題**

## 読み方

教室棟の教室は中心間で10m前後しか離れていない。だから:

| 出たもの | 結論 |
|---|---|
| Apple登録0件 / Google 404 | その地点でWiFi測位は効かない。GPS衛星だけになる（屋内なので実質不能） |
| 精度半径が20m以上 | 教室は区別できない。隣の部屋を自信たっぷりに指す |
| 隣の教室どうしの推定距離が実際の間隔より大幅に小さい | 2部屋が同じ点に潰れている＝区別できない |
| 別階の同じ位置の推定がほぼ同じ点 | 階は分かれない（Web APIに `floor` が無いので想定どおり） |

**この下見で肯定は証明できない。** 空いている平日に測った値は、来場者が増えた
日の値を予測しない。回線が混めば位置DBへの問い合わせ自体が通らなくなる。
できるのは否定の証明で、ここで区別できなければ本番でも区別できない、は確定する。

## 注意

- Apple 側は**非公式エンドポイント**（`gsloc` が叩く `gs-loc.apple.com`）。
  調査目的で広く使われているが、公式に提供されているものではない
- 記録される BSSID は周囲のAPのMACアドレス。測った場所が分かる情報なので、
  `tmp/` の外へ出す前に扱いを決める（`tmp/` は gitignore 済み）
- [WiGLE](https://wigle.net/) でも登録状況を見られるが、閲覧にアカウントが要る。
  緯度 35.6596〜35.6616 / 経度 139.7938〜139.7964 が豊洲キャンパスの範囲
